# Kard Radar

**Kard Lead Intelligence & Outreach System** — an internal web app for Kal's Digital that finds businesses likely to benefit
from Kard *right now*, explains why with evidence, and queues personalised outreach.

It does not rank by follower count. It ranks by **evidence of customer-journey friction** (no website, "DM for price",
WhatsApp-only ordering, generic link-in-bio) combined with **evidence of current growth activity** (launches, new
collections, events, promotions), and it shows every point it awards.

The technical plan (architecture, schema, scoring, API strategy, costs, V1 vs future) is in [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Environment variables

All configuration lives in `.env` (git-ignored) or real environment variables. Nothing secret ever reaches the browser;
`/api/status` only reports whether a key is set.

| Variable | Required | Purpose |
|---|---|---|
| `ADMIN_PASSWORD` | **yes** | The single admin login. `python server.py --init` generates one. |
| `SESSION_SECRET` | **yes** | ≥ 32 chars; signs the session cookie. Generated by `--init`. |
| `SECURE_COOKIES` | prod | Set `1` when served over HTTPS so the cookie is `Secure`. |
| `KARD_DB_PATH` | no | SQLite path (default `data/kard_radar.db`). |
| `DATABASE_URL` | no | `postgresql://…` for Postgres/Supabase instead of SQLite (needs `pip install "psycopg[binary]"`). |
| `ANTHROPIC_API_KEY` | optional | Enables AI business analysis and AI outreach drafts. |
| `ANTHROPIC_MODEL` | no | Default `claude-opus-5`. `claude-sonnet-5` is roughly 60% cheaper. |
| `AI_EFFORT` | no | `low` / `medium` (default) / `high` / `xhigh` / `max`. |
| `SERPER_API_KEY` | optional | Search discovery via Google results (web, `site:instagram.com`, `site:tiktok.com`). |
| `BRAVE_SEARCH_API_KEY` | optional | Alternative search provider (used when Serper is not set). |
| `GOOGLE_PLACES_API_KEY` | optional | Google Places API (New) discovery — venues with phone / website / rating. |

Restart the server after changing `.env`.

## How it works

```
COLLECT     website + bio-link fetch (polite, cached 7 days, robots.txt, SSRF-guarded) · social snapshots · search results · CSV
NORMALIZE   handles, domains, +234 phones, name keys, loose dates ("3 days ago", 20/09/2026)
DETECT      deterministic rules → signals with state yes / no / unknown and evidence refs (obs:12, field:website_status)
AI          optional: Claude proposes extra signals + pain points + drafts; anything citing non-existent evidence is dropped
SCORE       pure function → Opportunity (100), Kard Fit, Business Quality, Confidence — every point is a line item
OUTREACH    template drafts from observed signals (free) + AI drafts (Instagram, TikTok, WhatsApp, email)
```

**Scoring (default weights, editable in Strategy):** Business fit 20 · Social activity 20 · Digital presence gap 30 ·
Buying signals 20 (5 each, capped, recency window; undated = 3; stale = 0) · Accessibility 10.
Unknown data earns no points and is displayed as "Unknown" — "No website found" only counts when a check was actually
done (search lookup, Google Maps listing, or you ticking "I checked — no website").

**Kard Fit** = 60% gap + 25% fit + 15% friction depth. **Business Quality** = 35% social activity + 25% brand/presentation
+ 15% audience size (banded, supporting only) + 15% marketing activity + 10% contactability. They are deliberately separate.

**Precedence:** manual override > rule "yes" > rule "no" > AI "yes" > unknown. AI can fill gaps, never overrule observed data.

**Cost control:** AI runs only on request, is skipped when the evidence hash is unchanged ("Force AI refresh" overrides),
and every call's tokens and estimated cost are logged (Strategy → AI usage). Discovery runs at most 6 queries per search.

**Duplicates:** Instagram handle, TikTok handle, website domain, phone (E.164) and email are strong keys; normalised name +
city is a probable match (only when no strong key conflicts). Manual add warns, CSV import merges or skips, discovery
flags "In Radar".

**Learning data:** `outcomes` stores the funnel (contacted → responded → interested → meeting → proposal → purchased,
revenue) plus the score, category points and signal list frozen at first contact. Export it from Import / export.

## Data & platform rules

- Instagram, TikTok, Facebook, X, Threads and LinkedIn pages are **never fetched** (hard block-list). Social data comes
  from search-engine results, what you paste/enter, or future approved APIs.
- Only public business information is stored. No personal data beyond what a business publishes for customers.
- The fetcher refuses private/loopback IPs and re-validates every redirect. It honours `robots.txt` (e.g. Linktree pages
  that disallow bots are reported as "blocked by robots.txt", not scraped around).

## Deployment

### Vercel

`pyproject.toml` points Vercel at the WSGI app in `radar/wsgi.py` (`[tool.vercel] entrypoint = "radar.wsgi:app"`) and
lists the dependencies. Vercel's disk is temporary, so **a Postgres database is required** — the app refuses to run on
SQLite there and says so on the login screen.

1. In the Vercel project: **Storage → Create / connect database → Neon (Postgres)**. This injects `DATABASE_URL` /
   `POSTGRES_URL` automatically. Any Postgres URL (Supabase, etc.) set as `DATABASE_URL` also works.
2. **Settings → Environment Variables**: add `ADMIN_PASSWORD` and `SESSION_SECRET` (≥ 32 characters, e.g. the output of
   `python -c "import secrets; print(secrets.token_hex(32))"`). Optionally `ANTHROPIC_API_KEY`, `SERPER_API_KEY`,
   `BRAVE_SEARCH_API_KEY`, `GOOGLE_PLACES_API_KEY`.
3. Redeploy. Tables are created automatically on first request. Cookies are `Secure` by default on Vercel.

Notes: each request opens its own database connection (use Neon's pooled URL, which the integration provides). Research
and AI requests can take 10–60 s, within Vercel's default function duration.

### Any other host

Any host that runs a long-lived Python process works (Render, Railway, Fly.io, a VPS):

```bash
python server.py --host 0.0.0.0 --port $PORT
```

or any WSGI server with `radar.wsgi:app`.

- Put it behind HTTPS and set `SECURE_COOKIES=1`.
- SQLite needs a **persistent disk** (e.g. a Render disk mounted at `/data` with `KARD_DB_PATH=/data/kard_radar.db`),
  or use `DATABASE_URL` for managed Postgres.
- Login throttling is per client IP in memory (per instance on serverless); it only matters if you expose the app more
  widely than the internal team.

## Stack note

The brief preferred Next.js + TypeScript + Tailwind. Node.js is not installed on this machine and the brief required the
app to be run and tested here, so V1 is Python 3.13 (standard-library HTTP server + SQLite, official `anthropic` SDK) with
a build-free vanilla-JS frontend. The backend is a clean JSON API, so the frontend can be ported to Next.js later without
touching the research engine.
